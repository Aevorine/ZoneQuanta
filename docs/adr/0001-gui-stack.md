# 0001 界面技术选型：WPF + .NET 8

## 候选与取舍

| 方案 | 体积 | 常驻内存 | 透明 / 穿透 / 置顶 | 视觉上限 | 结论 |
|---|---|---|---|---|---|
| **WPF (.NET 8)** | 轻量版 0.5 MB（需运行时）/ 独立版 67 MB | 约 60 MB | 分层窗口 + 扩展样式，原生支持 | 矢量 + 自绘，动画成熟 | **采用** |
| WinUI 3 | 大（需 Windows App SDK） | 中 | 穿透与异形窗口需额外封装 | 高，Fluent 原生 | 打包与分发复杂，收益有限 |
| Avalonia | 中 | 中 | 需平台互操作 | 高，可跨平台 | 目标仅 Windows，不需要跨平台成本 |
| Tauri / WebView2 | 小 | 偏高（浏览器进程） | 穿透需手写 | 极高，CSS 自由 | 常驻多进程，违背「不卡顿」 |
| Electron | 大 | 高 | 可行 | 极高 | 体积与内存不符合要求 |
| Win32 + Direct2D | 极小 | 最低 | 完全可控 | 取决于投入 | 设置面板开发成本过高，可扩展性差 |

## 方向

- 桌面组件追求「几乎不存在」：自绘卡片、1 Hz 对齐秒边界、仅重绘变化的数字
- 设置面板追求「一眼找到、一步完成」：重要开关做成大磁贴放在控制台首屏
- 轻量版 + 独立版并行发布，更新时按当前版本类型取对应文件

## 后果

- 依赖 Windows；若以后需要跨平台，核心层（`Core`）无界面依赖，可复用
- 更新采用「重命名运行中的 exe 再替换」，无需额外更新器进程
